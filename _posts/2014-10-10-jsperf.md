<h2>A Speed Test</h2>
<h4>The Problem</h4>
The hiring assessment is drawing near, so many of us have started reviewing material during our free time. For me, that's generally on the 40 minute bus ride to-and-from Hack Reactor.

Here's the code I was working on today:

![Underscore source code for contains function](/assets/images/2014/10/Screen-Shot-2014-10-09-at-3-55-09-PM.png)

It's a reimplementation of the popular underscore library. The guy sitting next to me was a programmer and took note of this line:

![if the value at collection i is equal to target](/assets/images/2014/10/Screen-Shot-2014-10-09-at-4-06-15-PM.png)

He asked, "Why aren't you using `.indexOf()` there?" 

Aside from style--I like being very explicit in if-statements--I didn't have much of a reason. He felt that using a native JavaScript method would be better than a for-loop, but did not know. He suggested that I check out <a href='http://jsperf.com/'>JSPerf</a>, a performance evaluation tool for JavaScript.

<h4>Create A Performance Test</h4>
<a href='http://jsperf.com/'>JSPerf</a> has a lot of options, almost none of which I will use. It didn't find it necessary.

<ol><p></p>
<li>Starting on the <a href='http://jsperf.com/'>home page</a>, enter your details so that the site can remember you and your ownership of the tests.</li><p></p>
<li>Enter a title and description.
![Title and description](/assets/images/2014/10/Screen-Shot-2014-10-09-at-4-27-50-PM.png)
</li>
<li>A lot of my magic happens in the <i>Preparation code HTML</i> section. Inside a script tag define the functions you want to compare and the variables they need.
![Preparation code. Array declaration. Find is defined as 10. Function named triple equals loops using for. Function named Index of uses index of instead of the loop.](/assets/images/2014/10/Screen-Shot-2014-10-09-at-6-53-40-PM.png)
</li>

<li>Skip to the <i>Code Snippets to Compare</i> section. Here, I <u>implore</u> you to write useful test titles. My first test is named "Searching array for a value with a for loop". You know exactly what it does. Put your matching function from step three in the <i>Code</i> section. The parameters passed into the function are also the ones you defined before.

![Test window. Title. Async checkbox. Code box](/assets/images/2014/10/Screen-Shot-2014-10-09-at-6-58-43-PM.png)
<p>Repeat as needed for more tests by clicking <i>Add code snippet</i>.
![3 buttons. Beautify code. Add code snippet. Save test case](/assets/images/2014/10/Screen-Shot-2014-10-09-at-7-03-47-PM.png)
</p>
</li>
<li>Save your test by clicking *Save test case*. 
<h5>Warning!</h5>EVERY SINGLE TIME I save I get an internal server error. 
![](/assets/images/2014/10/Screen-Shot-2014-10-09-at-4-43-50-PM-1.png)
Ignore it! Your stuff saved. It does not even indicate that you had syntax errors. Back your URL up to its base (given your title) and hit enter:
![Base url to avoid internal server error.](/assets/images/2014/10/Screen-Shot-2014-10-09-at-7-10-32-PM.png)
</li></ol>

<h4>If You Have Errors</h4>
You may have made a mistake in your code at some point. JSPerf will tell you. 

![Errors on JSPerf](/assets/images/2014/10/Screen-Shot-2014-10-09-at-8-18-55-PM.png)

Type of the address of your test with `/edit` on the end to fix your code.

![Edit URL](/assets/images/2014/10/Screen-Shot-2014-10-09-at-8-20-15-PM.png)

If you have multiple revisions of your test, you can also type the revision number, then edit.

![Revision 5 edit URL](/assets/images/2014/10/Screen-Shot-2014-10-09-at-8-20-29-PM.png)
<h4>Run Your Tests</h4>
<p>(when everything is working)</p>
<ol>
	<li>Scroll down, past your beautiful prep code. You can either click on the <i>Run tests</i> button to run them all (recommended) or run them individually by clicking the test names on the left hand column.
![Test runner window where you click to run the tests](/assets/images/2014/10/Screen-Shot-2014-10-09-at-7-19-42-PM.png)
</li>
<li>Give it a sec. The tests will show how many Ops/sec (operations per second) can run. It will also make comparisons between the tests. 
![Numerical test results. Bar graph showing test results. Index of is faster than array loop](/assets/images/2014/10/Screen-Shot-2014-10-09-at-7-26-40-PM-1.png)
For the more visual among us, scroll down a bit and you will get a graphical representation.
![Bar graph showing test results. Index of is faster than array loop](/assets/images/2014/10/Screen-Shot-2014-10-09-at-7-26-50-PM.png)

If other users have run your code on <a href='http://jsperf.com/browse'>JFPerf's browse site</a>, there may be other systems represented by the graph, as is the case above.
</li>
</ol>

<h4>Summary</h4>

Here is the test we created:
http://jsperf.com/indexof-vs-tripleequal

Turns out using `indexOf` is about 13% faster than making your own for-loop. I wonder what JavaScript is doing under-the-hood?

JSPerf is not *perf*ect or all that easy to use, but it's a good tool for basic speed comparisons. (See what I did there?)
